175// The input archive must be able to answer "is this name present" without throwing.
176//
177// It is not a correctness requirement - try_serialize_direct falls back to catching the
178// exception - which is exactly why it needs asserting. Loading an entity probes every
179// serializable component type by name and most of those miss, so on an archive without
180// hasNextName the fallback costs a full stack unwind per absent component: measured at
181// ~2us each, ~30 per entity, and a 6x slowdown on every scene load, play start and script
182// recompile. Nothing would fail; it would just quietly get slow.
183//
184// If this fires after switching SER20_ASSOCIATIVE_ARCHIVE, give the newly selected archive
185// a hasNextName(const char*) const -> bool. It is a membership test over the current
186// level, not a comparison against getNodeName(): readers skip fields without consuming
187// them, so the name being asked for is often ahead of the cursor. See
188// simd::JSONInputArchive::hasNextName for the reference implementation.
189static_assert(is_loading_archive<ser20::iarchive_associative_t>(),
190 "iarchive_associative_t must be an input archive");
191static_assert(can_probe_names<ser20::iarchive_associative_t>,
192 "The selected associative input archive has no non-throwing hasNextName(). "
193 "See the comment above this assertion.");
194
195// The input archive must also be able to leave the nodes a failed load entered.
196//
197// try_load catches a failed load and carries on, which is only correct if the archive is back
198// at the node the failed load started in: otherwise every following name is looked up inside
199// the failed child, reads as absent and silently keeps its default. Give a newly selected
200// archive getNodeDepth() and restoreNodeDepth(); see simd::JSONInputArchive.
201static_assert(can_restore_nodes<ser20::iarchive_associative_t>,
202 "The selected associative input archive cannot restore its node depth after a failed load. "
203 "See the comment above this assertion.");
