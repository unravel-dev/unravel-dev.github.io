Detailed Description

A project's settings profiles, kept in step with their files: every change is written at once.

Changing a profile's name moves everything named after it: its folder, its kept releases (releases/<profile>) and its texture cache (cache/profiles/<profile>). Its build folder under the deploy location keeps its name, since it holds the user's builds.

auto unravel::deployment::project_profiles::load ( const fs::path & project_root,

deploy_settings & base_deploy,

Reads the profiles of the project at project_root.

A project from before profiles gets its first ones from deploy/deploy.cfg (make_profiles_from_legacy), and deploy.cfg is kept as deploy.cfg.before-profiles. A project with no profile gets Desktop. Releases kept before profiles, and the release their deploys patched, become the first desktop profile's whenever they are found (a teammate's project from before profiles merged in, say). The texture caches of profiles that no longer exist are deleted.

Parameters
base_deployThe shared deploy settings as loaded; their patch release from before profiles moves into a profile. The caller saves them, unless has_unkept_legacy_settings.
deploy_profileSet to the profile of the old target by a migration; otherwise left as it is.
Returns
What was wrong with the profiles' files, one sentence each.
