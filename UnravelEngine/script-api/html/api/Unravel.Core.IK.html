Class IK

Namespace
Unravel.Core

Inverse-kinematics helpers for skeletal chains.

Call these from OnUpdate. Scripts run after the animation system has evaluated the pose and before skinning, so bone writes made there are what gets rendered. Writing bones from OnFixedUpdate does not work - animation will overwrite them later in the frame.

Every method returns true when a pose was written. A false means the chain was too short, the goal was not finite, or the weight was zero - not that the target was out of reach (an unreachable target still produces a valid stretched pose).

The position solvers only orient the bones that drive the chain, never the end effector itself, so a solved foot keeps the orientation animation gave it. Follow a position solve with SetIKRotation(Entity, Quaternion, float) to pin a foot to a slope or keep an aimed hand level.

Poles must come from a reference the solve does not move - the character root, or a dedicated hint entity. A pole derived from the end effector's own transform closes a feedback loop: the solve rotates the effector, the pole follows it, the chain chases the pole, and the limb spins.

GetBoneAxis(Entity)

Bone-local direction from entity toward its first child, i.e. the axis the bone visually runs ALONG. Returns Vector3.forward for leaf bones.

Use this with SetIKAim(Entity, Vector3, Vector3, Vector3, Vector3, float, float) only when you want to point the bone itself at something - a barrel, a tentacle, a limb. It is the wrong axis for a "face the target" aim on a spine, chest or head: aiming a spine along its own length points the torso at the target and folds the character in half. Which axis represents a bone's FACING cannot be derived from the skeleton (that is what a humanoid avatar mapping is for), so pass it explicitly - Vector3.forward for most rigs.

GetFacingAxis(Entity, Vector3)

Bone-local axis of entity that currently points along worldDirection, snapped to the nearest signed unit axis.

This is how you get the forwardAxis for SetIKAim(Entity, Vector3, Vector3, Vector3, Vector3, float, float) on a torso or head without guessing. A rig authored with the chest's local -Z out of the front is structurally identical to one with +Z out of the front, and importers do not normalise it - so ask the rig which local axis lines up with the character's forward:

spineAimAxis = IK.GetFacingAxis(Spine, transform.forward);

Sample it in a neutral pose (OnStart is fine). Snapping means a spine slightly bent by the current animation frame still resolves cleanly.

Contrast with GetBoneAxis(Entity), which returns the axis the bone runs ALONG - a different question with a different answer.

SetIKAim(Entity, Vector3, Vector3, Vector3, Vector3, float, float)

Points a bone-local axis at target.

Imported rigs rarely run their bones along +Z - Mixamo bones run along local +Y - so pass the rig's actual axis, or GetBoneAxis(Entity) to derive it from the skeleton.

SetIKPositionFabrik(Entity, Vector3, Vector3, int, int, float, float)

Solves a FABRIK IK chain so the end effector reaches target. pole is a world-space hint for which side of the (root -> end) line intermediate joints should bend toward. Without a pole, FABRIK may pick any geometrically valid bend direction - which on steep slopes causes knees to collapse inward. Pass Vector3.zero to disable the constraint.

SetIKPositionTwoBone(Entity, Vector3, Vector3, float, float)

Analytical two-bone IK (hip-knee-foot or shoulder-elbow-hand). Prefer this over FABRIK for limbs: it is exact, single-pass, and cannot oscillate. pole decides which side of the limb plane the knee (or elbow) bends to - typically a point in front of the character for legs, or off to the side for arms.

Requires exactly three joints above and including entity and returns false otherwise; it will not silently fall back to a different solver.

public static bool SetIKPositionTwoBone(Entity entity, Vector3 target, Vector3 pole, float weight = 1, float soften = 0)
